# Linet: дизайн

Связка Android-смартфона и Linux-ноутбука в духе экосистемы Apple: файлы, уведомления,
общий буфер обмена, Handoff, разблокировка телефоном, экран в обе стороны.

Пет-проект для себя: POCO X6 Pro (HyperOS 3) и ноутбук на Hyprland + Caelestia.
Документ описывает то, что сделано; планы — в конце.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Протокол | Свой, `linet/1` | Нужны фичи, которых нет в KDE Connect |
| Десктоп | Rust | tokio, quinn (QUIC), zbus (D-Bus), wayland-client |
| Android | Kotlin + Jetpack Compose | NotificationListener, PackageInstaller, FileProvider |
| Общий код | `linet-core` на Rust, в Android через uniffi | Протокол, крипто и сеть написаны один раз |
| Транспорт | QUIC поверх UDP, TLS 1.3 | Шифрование из коробки, несколько потоков: файл не тормозит уведомления |
| Сериализация | CBOR (serde + ciborium) | Неизвестные поля и сообщения пропускаются — протокол расширяется без поломок |
| Экран телефона → ноутбук | scrcpy поверх ADB | Зрелый инструмент; Linet только включает беспроводную отладку на время показа |
| Экран ноутбука → телефон | wayvnc + AVNC | Работает на Hyprland, умеет шифрование и пароль |

## Протокол

### Идентичность и сопряжение

- У каждого устройства долговременный ключ **Ed25519** и самоподписанный сертификат.
  Идентичность — `sha256(сертификат)`, короткий id — первые 8 байт в hex.
  Linux: `~/.local/share/linet/identity.key.der` (0600); Android: приватный каталог
  приложения (TLS-стек в Rust должен видеть ключ, поэтому не Keystore).
- Роли фиксированы: **ноутбук — сервер, телефон — клиент.** Телефон сам решает,
  когда подключаться, и ничего не слушает (кроме подсказок в точке доступа, см. ниже).
- **Сопряжение:** `linetctl pair` показывает QR с
  `linet://pair?v=1&fp=<отпечаток>&s=<секрет 128 бит>&a=<адреса>`. Телефон проверяет
  сертификат ноутбука по `fp` и доказывает знание секрета:
  `HMAC-SHA256(s, "linet-pair-v1" ‖ fp_ноутбука ‖ fp_телефона)`. Приглашение живёт
  2 минуты и одноразовое. Затем новое устройство **подтверждается на ноутбуке** кнопкой
  в уведомлении (1 минута).
- Дальше — только mTLS с закреплёнными сертификатами; неизвестные отклоняются
  на рукопожатии.

### Соединение

- QUIC (quinn), ALPN `linet/1`, UDP 47321.
- Управляющий поток: `u32 длина ‖ CBOR(Envelope { id, reply_to, body })`, кадр до 16 МБ
  (из-за картинок буфера обмена).
- Каждый файл — отдельный однонаправленный поток: `u64 id ‖ данные`.
- Keepalive шлёт только ноутбук, раз в 10 минут; idle-таймаут 30 минут.
- Ключ stateless reset выводится из ключа устройства: после перезапуска демона телефон
  сразу получает валидный reset и переподключается.
- Запрос без ответа 10 с закрывает сеанс (процесс на телефоне мог быть убит).
  Запросы, ждущие человека (разблокировка, VNC), используют длинный таймаут и сеанс не рвут.

### Сообщения

`Hello`, `PairRequest`/`PairAccept`/`PairReject`, `Ping`/`Pong`,
`FileOffer { id, name, size, mime, purpose }` / `FileAccept { id, offset }` / `FileReject`,
`Notification`, `NotificationRemoved`, `NotificationAction`, `NotificationDismiss`,
`Clipboard { text }`, `ClipboardImage { mime, data }`, `Handoff { url, title }`,
`UnlockRequest`/`UnlockResponse`, `Battery { level, charging }`,
`ScreenShare { enable }`/`ScreenShareResult`, `VncRequest { extend, width, height }`/`VncResult`/`VncStop`.

Новые варианты добавляются в конец; незнакомый получатель превращает их в `Unknown`
и соединение не рвёт. Новые поля — с `#[serde(default)]`.

### Сеть

- **mDNS** `_linet._udp` — только в **доверенных сетях**: подключение NetworkManager
  (Wi-Fi/Ethernet), через которое уже подключался телефон, запоминается само
  (`trusted_networks.json`). В остальных сетях ноутбук себя не объявляет.
- Телефон помнит адреса ноутбука и пробует их параллельно; при неудаче — короткий
  (15 с) поиск через NSD, когда появился Wi-Fi или включился экран.
- **Точка доступа телефона:** телефон — шлюз ноутбука, и ноутбук, пока не подключён,
  шлёт на шлюз подписанную подсказку (UDP 47322, 82 байта:
  `"LNH1" ‖ порт ‖ время ‖ IPv4 ‖ Ed25519-подпись`). Телефон слушает её только на
  интерфейсе своей точки доступа и только пока нет соединения, проверяет подпись по
  сохранённому сертификату ноутбука. Подсказка лишь говорит, куда стучаться.

## Функции

### Файлы
- Телефон → ноутбук: «Поделиться → Отправить на ноутбук»; на ноутбуке — `~/Downloads/Linet`,
  уведомление «Открыть» / «Папка».
- Ноутбук → телефон: `linetctl send`, «Отправить на телефон» в меню запуска,
  «Открыть с помощью» и сценариях Nautilus, клик по значку в трее; на телефоне — «Загрузки/Linet».
- **Докачка:** недокачанный `.part` (имя из отпечатка отправителя, имени и размера)
  остаётся; повторная отправка продолжает с `offset`. Отправитель при обрыве сам ждёт
  переподключения до 2 минут и продолжает (до 3 попыток).
- Имя очищается от путей; сохранение через жёсткую ссылку не перезаписывает файлы;
  лимит 8 ГБ на ноутбуке и 4 ГБ на телефоне.

### Уведомления
- `NotificationListenerService` → ноутбук; иконка приложения передаётся раз за сеанс.
- Пропускаются постоянные, тихие и групповые; **фильтр по приложениям** в Linet.
- Кнопки работают с ноутбука; ответ — через fuzzel (Caelestia не умеет inline-reply).
- Смахивание синхронизируется в обе стороны. Caelestia после нажатия кнопки сама закрывает
  уведомление «пользователем» — это не считается смахиванием.
- Текст экранируется: Caelestia разбирает Markdown/HTML в теле и HTML в заголовке.

### Буфер обмена
- Ноутбук: `wl-paste --watch` (текст и картинки отдельно). Пароли с пометкой
  `x-kde-passwordManagerHint` не пересылаются.
- Ноутбук → телефон автоматически; телефон → ноутбук — плиткой, «Поделиться»
  или кнопкой (фоновое чтение буфера Android запрещает).
- Текст, похожий на пароль, помечается на телефоне чувствительным. Очистка буфера
  на ноутбуке очищает телефон (2 минуты; `wl-copy --clear` ловится опросом).
- Картинки до 12 МБ; на телефоне — через FileProvider. Лента Gboard такие картинки
  не вставляет (ограничение Gboard), долгое нажатие → «Вставить» — работает.

### Handoff
- Firefox/Chromium: расширение (кнопка, Ctrl+Alt+P, контекстное меню) → `linet-nmh` →
  уведомление «Продолжить» на телефоне. `linetctl open <url>`.
- Телефон → ноутбук: «Поделиться» ссылкой → уведомление, клик открывает в браузере.
- Только `http(s)`.

### Батарея и трей
- Телефон шлёт заряд при подключении и при изменении. Значок Linet в трее Caelestia
  (StatusNotifierItem) показывает заряд; клик — выбор файлов для отправки.
- Уведомления на 20 % и 10 %. `linetctl stats` — скорость разряда (%/ч без зарядки).

### Разблокировка и автоблокировка
- **Разблокировка:** крышка (UPower), выход из сна (logind) или `linetctl unlock` →
  запрос телефону по mTLS → IPC Caelestia `lock unlock` (hyprlock — SIGUSR1). Без PAM и root;
  пароль работает всегда. Телефон в руке и разблокирован — согласие сразу (настраивается),
  иначе уведомление с кнопкой, требующей разблокировки телефона. Linet тратит ~0,4 с,
  после сна ~6 с уходит на подъём сети.
- **Автоблокировка:** ввода нет больше минуты (`ext-idle-notify`) — ноутбук раз в 20 с
  пингует телефон; не ответил — экран блокируется. Пока ты работаешь, телефон не трогается.

### Экран телефона на ноутбуке (scrcpy)
- `linetctl screen`, пункты меню «Экран телефона» и «Приложение с телефона»
  (`--pick-app`: приложение в своём окне на виртуальном дисплее).
- Телефон на проводе — по USB. Иначе телефон по запросу включает беспроводную отладку
  (`WRITE_SECURE_SETTINGS`, выдаётся один раз по USB), ноутбук находит порт через
  `adb mdns services`; после показа отладка выключается, при обрыве связи — тоже.
  Сопряжение кодом не нужно: ключ ноутбука уже разрешён по USB.
- Беспроводная отладка Android работает только в Wi-Fi, не в собственной точке доступа.
- Окна scrcpy в Hyprland плавающие (`~/.config/caelestia/hypr-user.lua`).

### Экран ноутбука на телефоне (wayvnc)
- В приложении «Показать экран» и «Второй монитор». Ноутбук запускает wayvnc на адресе,
  видимом телефону, с одноразовым паролем и шифрованием (TLS или RSA-AES), телефон
  открывает ссылку `vnc://…` в AVNC.
- Второй монитор — виртуальный экран Hyprland (`hyprctl output create headless` +
  `hl.monitor` через `eval`), всегда альбомный; масштаб — самый крупный, при котором
  высота ≥ 720 логических точек (POCO: 1,6 → 1690×760).
- Клавиатура: одна группа «linet» (US, кириллица на уровнях 3–4) — с `us,ru` wayvnc
  оставался в `ru` и печатал «ю» вместо «.».
- 60 кадров, курсор рисует клиент. Закрывается, когда клиент ушёл, не пришёл за минуту
  или пропала связь с телефоном.

### Обновление приложения
- `linetctl update-phone` шлёт APK с `purpose = "app-update"`; телефон кладёт его в кэш,
  уведомление открывает Linet, а тот — системный установщик (из фона HyperOS окно не
  показывает). Android сверяет подпись. `versionCode` — число коммитов + 100.

## Безопасность

Модель угроз: чужой в той же сети, чужие приложения на телефоне, любой, кто пишет
в мессенджер (его текст попадает в уведомления), человек у ноутбука.

- Подключиться может только сопряжённое устройство; mDNS и подсказки влияют только на адрес.
- Новое устройство подтверждается кнопкой на ноутбуке: открыть окно сопряжения через
  D-Bus может любой процесс пользователя, нажать кнопку — нет.
- «Поделиться» принимает только чужие `content://` URI.
- Беспроводная отладка и wayvnc открыты только на время показа экрана.
- Ключ подписи APK — `~/.config/linet/linet-signing.jks`; держать в бэкапе.

Известные ограничения: разблокировка не проверяет близость телефона; открытое на экране
телефона приложение может отправить текст в буфер ноутбука через «Поделиться»;
уведомления остаются в истории Caelestia.

## Батарея телефона

- Никаких WakeLock (кроме времени передачи файла), AlarmManager, WorkManager и опроса.
- Телефон не шлёт keepalive; ноутбук — раз в 10 минут, соединение переживает сон.
- Переподключение по событиям (Wi-Fi, экран, кнопка); пауза между попытками в сне не тикает.
- Заряд шлётся только при изменении; в ядре один рабочий поток tokio.
- Экран телефона и VNC тратят батарею только пока открыты.

## Память ноутбука

glibc держала отдельную арену на поток и после крупных буферов (картинки буфера обмена)
не возвращала память: за 3 дня 517 МБ. Теперь `mallopt` (2 арены, порог mmap 1 МБ),
два рабочих потока, ограниченные списки уведомлений: под нагрузкой ~11 МБ.

## Проверка

- `scripts/e2e.sh` — отдельный демон на своей шине D-Bus против `linet-sim`: отказ
  сопряжения без подтверждения, ping, файлы в обе стороны, докачка, VNC, память под
  нагрузкой, уборка. Запускать перед обновлением.
- `linetctl stats` — подключения, трафик, память демона, разряд телефона.
